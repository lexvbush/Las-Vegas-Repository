# Las Vegas Documentary — Archival Image Workflow

Tooling for tagging archival TIFs with provenance metadata before they go up to
Lightroom, so the archive source travels with the file and comes back intact
when the team re-downloads it.

## Why metadata goes in before upload

Lightroom's cloud version **never writes metadata back into original files** —
it keeps changes in Adobe's catalog. Whatever is embedded in the TIF at upload
time is exactly what a teammate gets when they download the original again.
Tagging before upload is the only way the archive source survives the round trip.

Lightroom's web UI also only *displays* a few fields: Title, Caption, Creator,
Copyright and keywords. Anything the team needs to read at a glance has to live
in those. So the catalog ID is the Title, the archive name and catalog ID are packed
into the Caption, and the credit line into Copyright — all visible in the
browser.

## Provenance survives in four layers

| Layer | Carries | Survives |
|---|---|---|
| Filename | `CHS-5711.tif` — the archive's catalog ID, verbatim | everything, including metadata stripping |
| Visible fields | Title, Caption, Creator, Copyright | Lightroom web, any download |
| Embedded fields | IPTC Source, Credit, Usage Terms, Web Statement | any XMP/IPTC-aware tool |
| `manifest/master_manifest.csv` | the full record, in git | independent of any file |

## Setup

ExifTool does the embedding.

```bash
brew install exiftool          # macOS
# Windows: https://exiftool.org  (get the Windows Executable, add to PATH)

exiftool -ver                  # confirm it's on PATH
```

No Python packages needed — standard library only.

## Use

Point `--folder` at the TIFs. On this setup that is `Vegas Downloads Full Folder`.

```bash
F="$HOME/Vegas Downloads Full Folder"

python3 scripts/lvtag.py audit  --folder "$F"              # what's on disk vs. the sheet
python3 scripts/lvtag.py plan   --folder "$F" --pending    # preview, writes nothing
python3 scripts/lvtag.py apply  --folder "$F" --pending --stage
python3 scripts/lvtag.py verify --folder "$F"              # read it back out
python3 scripts/lvtag.py rename --folder "$F" --apply      # filename provenance
```

To refresh the manifests from Airtable, or push reviewed corrections back:

```bash
export AIRTABLE_TOKEN=pat...                     # read, plus write for the push
python3 scripts/pull_manifest.py                 # Airtable -> the two CSVs
python3 scripts/push_manifest.py --csv manifest/caption_proposal.csv
python3 scripts/push_manifest.py --csv manifest/caption_proposal.csv --apply
```

`--pending` limits to rows whose `metadata_attached` column is not `Yes`
(465 of 731 as of 2026-09-02). `--stage` copies each tagged file into
`daily/<today>/`, which is the folder to drag into Lightroom.

`apply` keeps a `*_original` backup beside each file until you pass
`--no-backup`. Re-running `apply` is safe — keywords are cleared and rewritten
rather than appended, so files don't accumulate duplicates.

### Commands

| Command | Does |
|---|---|
| `audit` | Matches files to sheet rows, reports drift, writes `manifest/audit_report.csv` |
| `plan` | Shows what would be written, touches nothing |
| `apply` | Embeds the metadata via exiftool |
| `verify` | Reads the fields back to confirm they stuck |
| `rename` | renames to `<catalog id>.tif` — dry run unless `--apply` |
| `daily` | Copies matched files into `daily/<today>/` |
| `keywords` | Flags keywords outside the controlled vocabulary |

## What's tracked

- `manifest/master_manifest.csv` — 731 rows, generated from Airtable by
  `scripts/pull_manifest.py`. Do not hand-edit: push corrections to Airtable
  with `scripts/push_manifest.py`, then pull.
- `manifest/audit_report.csv` — regenerated by `audit`
- `vocabulary/` — 239 controlled keyword terms, 41 merge rules
